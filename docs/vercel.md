# Вход на Vercel с существующим Firebase

Ошибка опубликованной версии: запрос `POST /api/local` возвращал 404. Плагин Vite обслуживает этот маршрут локально, но не входит в статическую production-сборку. Теперь `api/local.mjs` — отдельная Vercel Node Function, использующая ту же серверную логику, что локальный проект.

## Настройка

Используется существующий проект `cyberlearn-12348`; новый Firebase-проект и Cloud Functions не требуются. Ключ Firebase из браузерного приложения не заменяет серверный доступ.

1. Сохраните закрытую резервную копию старой Realtime Database. Нельзя публиковать экспорт или сервисные ключи в Git.
2. Примените `database.rules.json` в существующей Realtime Database: прямые чтение и запись из браузера закрыты. Перед записью сервер проверяет, что новый раздел не читается без авторизации.
3. В настройках Vercel → Environment Variables добавьте **серверные** переменные, без префикса `VITE_`:
   - `FIREBASE_SERVICE_ACCOUNT` — JSON сервисной учётной записи этого Firebase-проекта. Пользователь получает и сохраняет ключ в закрытых настройках самостоятельно.
   - `CYBERLEARN_TEACHER_LOGIN` — `imyourteacher`.
   - `CYBERLEARN_TEACHER_PASSWORD` — пароль от 12 символов для первого запуска единственного учителя. Сохраняется только солёный PBKDF2-хеш. После инициализации переменную можно убрать: существующий пароль не перезаписывается.
   - `CYBERLEARN_DATABASE_URL` — необязательный адрес существующей Realtime Database; по умолчанию используется адрес проекта из прежнего приложения.
4. Если в Firebase уже есть реальные классы, выполните перенос из раздела ниже **до первого запроса нового API**. Затем разверните новую версию репозитория на Vercel. Клиент продолжает обращаться к `/api/local` того же домена; CORS-перенаправление и открытые клиентские правила не нужны.
5. Проверьте вход учителя, создание папки и класса, вход ученика по коду, сохранение прогресса и поднятую руку с двух разных браузеров.

## Данные и ограничения

Новая серверная структура находится в `schoolServerV1`; старые разделы базы **не удаляются и автоматически не импортируются**. Для переноса добавлен `npm run import:firebase`. С серверным ключом в закрытой переменной окружения он по умолчанию только читает старые данные и показывает количество переносимых классов и учеников. Если преподавателей несколько, задайте `CYBERLEARN_LEGACY_TEACHER_ID` выбранного владельца. После проверки запустите `npm run import:firebase -- --apply`, задав новый пароль и `CYBERLEARN_MIGRATION_BACKUP` — имя нового приватного резервного файла, например `.cyberlearn/firebase-legacy-backup.json`.

Перенос сохраняет ID учеников, коды их классов, прогресс, купленные старые аватары и рамки. Старые пароли исключаются; ученики продолжают входить по коду и имени, преподаватель получает выбранный новый пароль. Если новая серверная структура уже создана, перенос остановится, чтобы не перезаписать её. Дублирующиеся имена внутри класса и коды разных классов также останавливают перенос. Переносятся только классы выбранного преподавателя и задания с явной связью с ними; остальная база остаётся неизменной. Существующий скрипт `functions/migrate.mjs` предназначен для прежней callable-архитектуры, а не для `schoolServerV1`.

Сессия — HttpOnly/Secure cookie; в хранилище сохраняется хеш токена. У серверного API остаются проверки владельца класса и роли. Запись использует ETag и условный PUT: при одновременном сохранении сервер перечитывает данные, не затирая работу другого ученика. Попытки входа ограничены через общее хранилище, а не память одного экземпляра функции.

Для небольших классов хранится единый JSON-снимок; это простой вариант, но при большом количестве учеников и частых одновременных записях потребуется разделить данные по классам и операциям. Решения учебных заданий проверяются в браузере; это не защищённая экзаменационная среда.

Развёртывание нельзя считать завершённым до проверки опубликованного API. Локальная проверка серверной логики: `npm run check:cloud`; файл и хостинг проверяются отдельно: `npm run check:school`.

Официальные справочники: [Vercel Node Functions](https://vercel.com/docs/functions/runtimes/node-js), [серверная авторизация Firebase REST](https://firebase.google.com/docs/database/rest/auth), [условные запросы Firebase](https://firebase.google.com/docs/database/rest/save-data).
