# CyberLearn

Учебная платформа для 3–7 классов: 320 заданий, тренажёры, кабинеты ученика и учителя, косметика и прогресс.

## Локальный запуск

Нужен Node.js 22.

```sh
npm ci
npm ci --prefix functions
npm run dev
```

Приложение использует Firebase Authentication и callable-функцию `api` в регионе `europe-west1`. До развёртывания новой серверной части вход и сохранение через новый клиент недоступны. Ключ Gemini не требуется. Публичный Firebase API key идентифицирует проект; он не заменяет проверку прав.

## Проверки

```sh
npm run check
npm run build
npx playwright install chromium
npm run check:browser
npm audit
npm audit --prefix functions
```

`check` проверяет типы, весь учебный каталог, косметику, начисления, интерпретатор, конфигурации тренажёров, теорию и регрессии. Серверные тесты используют модель RTDB, включая транзакции и контроль прав; они не заменяют проверку в Firebase Emulator Suite или staging.

Браузерные тесты запускают отдельный Chromium и локальный Vite на порту 3101. Для Python/SQL требуется доступ к CDN Pyodide. Python работает в отдельном Worker; бесконечное выполнение прекращается через 5 секунд, загрузка среды — через 60 секунд. JavaScript выполняется в отдельном Worker, SQL — в SQLite с учебными данными. Вывод сравнивается с исполнением эталонной программы, а не подменяется заранее записанным текстом. Shell — явно учебный симулятор файловой системы и Git, без доступа к компьютеру и настоящей сети.

## Переход на защищённую серверную часть

Это изменение требует согласованного развёртывания сервера, правил и клиента. Не публикуйте только новый клиент.

1. В Firebase Console проверьте проект `cyberlearn-12348`, включите Firebase Authentication и убедитесь, что домен приложения разрешён. Для Cloud Functions нужен тариф с поддержкой Functions и права на развёртывание.
2. Экспортируйте полную RTDB в закрытое резервное хранилище. Запланируйте короткую остановку старого клиента: старый клиент не совместим с закрытыми правилами.
3. Авторизуйте Firebase CLI и административные Application Default Credentials. Не добавляйте сервисные ключи в репозиторий.
4. Выполните `npm run build:functions`. Разверните `database.rules.json`: `firebase deploy --only database`. Правила запрещают прямое чтение и запись; все действия выполняет сервер после проверки токена и роли.
5. Предварительно проверьте миграцию: `node functions/migrate.mjs`. Она остановится при дублирующихся ID/именах или неоднозначном классе. Исправьте такие случаи административно, не удаляя инвентарь.
6. Укажите абсолютное имя нового приватного файла в `CYBERLEARN_MIGRATION_BACKUP` и запустите `node functions/migrate.mjs --apply`. Миграция хеширует пароли через scrypt, удаляет открытые пароли, восстанавливает однозначные старые связи классов и сохраняет ID, XP, деньги, завершённые задания и косметику. Резервный файл содержит старые пароли — храните его приватно.
7. Разверните сервер: `firebase deploy --only functions`. Для выпуска custom tokens рабочему сервисному аккаунту может понадобиться роль Service Account Token Creator. Проверьте вход учителя, выдачу пароля ученику, чужой класс, покупку, завершение и повторное сохранение задания в staging.
8. Выполните `npm run build` и опубликуйте `dist` на текущем хостинге. Если используется Firebase Hosting: `firebase deploy --only hosting`.

Старый пароль учителя работает после миграции, включая исторические короткие пароли. Новым аккаунтам нужен пароль от 8 символов. Ученики без старого пароля получают новый через кнопку «Выдать новый пароль» в карточке ученика. Имя и код класса больше не дают доступ к чужому аккаунту. Учитель без исторического пароля требует административного восстановления: задайте `CYBERLEARN_NEW_PASSWORD` и выполните `node functions/resetTeacherPassword.mjs <teacher_uid>`.

Старые сессии из `localStorage` не используются: после обновления нужен повторный вход. Кэши браузера не начисляют награды и не являются источником серверного прогресса. Для старых миссий, которые существовали только на компьютере учителя, создайте их заново в нужном классе: автоматически назначать общий локальный каталог неизвестному классу небезопасно.

Сервер выбирает цены и награды из каталога, проверяет владельца класса и использует транзакции. Повторное завершение не начисляет награду дважды. Проверка решений и результатов тренажёров пока выполняется в браузере: система не является защищённой экзаменационной средой, а целенаправленную подделку результатов собственных заданий через API нужно закрывать отдельной серверной проверкой решений.

## Локальное тестирование без Firebase

`npm run dev` на `http://127.0.0.1:3000/` или `localhost` включает локальный режим автоматически. На экране входа доступны кнопки «Тестировать как ученик» и «Тестировать как учитель». Для ручного создания аккаунта используйте код класса `TEST01` и пароль от 8 символов. Учитель может создать другие локальные классы и сбросить пароль ученика.

Аккаунты, классы, задания учителя, прогресс, попытки и покупки хранятся только в localStorage этого браузера (`cyberlearn_local_demo_v1`). Выход удаляет сессию, но сохраняет данные аккаунта. Локальные данные не отправляются в Firebase и не синхронизируются между браузерами. Пароли сохраняются как хеш с солью.

В production-сборке локальный режим отключён. Для проверки Firebase через dev-сервер задайте `VITE_LOCAL_DEMO=false npm run dev`. Проверка локального режима: `npm run check:local` (Playwright, включая отсутствие запросов Firebase, восстановление сессии, покупки, повторную отправку результата и работу классов).
